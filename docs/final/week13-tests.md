## Test 1 Spawn position within screen bounds
**Type:** Regression test

**What it protects:**
Energy objects always spawn fully visible within the screen boundaries.

**Which issue it covers:**
During Godot 4.6.1 migration, `shape.extents.x` was removed causing 
the spawn boundary calculation to silently fail. `half_w` defaulted 
to `16.0` which was too small, resulting in drops spawning partially 
or fully off screen and becoming uncatchable. Fixed by replacing the 
collision shape calculation with a fixed `80px` screen margin.

**Test logic:**
Verifies that any spawn x position generated by `randf_range(80, screen_w - 80)` 
is always within the valid screen range.

## Test 2 Score does not change after game over
**Type:** Regression test

**What it protects:**
Score and attempts values are frozen the moment game_over becomes true.

**Which issue it covers:**
Active drops continued to trigger collision events for several frames 
after game over was declared. This allowed score to increment or 
decrement after the scoreboard appeared. Fixed by adding 
`if game_over: return` at the top of all collision functions and 
immediately clearing all drops with `queue_free()` on game over.

**Test logic:**
Simlates the game_over guard confirms score stays at 10 when 
game_over is true.

## Test 3 Drop speed is constant without physics
**Type:** Refactor test

**What it protects:**
Drop objects fall at a predictable constant speed with no acceleration.

**Which issue it covers:**
Original implementation used `RigidBody2D` with `linear_velocity`. 
In Godot 4.6.1, default gravity and linear damping caused drops to 
accelerate uncontrollably as they fell, making the game unplayable 
at any speed setting. Refactored to `Area2D` with manual 
`position.y += speed * delta` movement, completely removing physics 
engine involvement.

**Test logic:**
Calculates expected position after one frame at 60fps with speed 150.0 
and verifies it matches `2.4px` with a tolerance of `0.01`.

## Test 4 Messenger does not text when game over
**Type:** Reliability test

**What it protects:**
The Messenger bot dialogue box cannot appear over the scoreboard 
after game over triggers.

**Which issue it covers:**
`MessengerTimer` runs on an independent 15-second loop with no 
awareness of game state. If the timer worked at the exact moment 
game over triggered, the dialogue box would appear on top of the 
scoreboard obscuring the final score. Fixed by adding 
`if game_over: return` at the top of `_on_MessengerTimer_timeout()`.

**Test logic:**
Simulates the game_over guard in the messenger function — confirms 
no message is sent when game_over is true.
